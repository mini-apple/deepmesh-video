# 시연 스크립트 / 실행 방법 정리

> 방어 시연·공격 시연·배경 트래픽에 쓰는 스크립트가 각각 어떤 파일이고, 어떤 명령으로 실행하는지 정리. (2026-09-11 기준)
>

## 1. 스크립트 파일 한눈에

| 파일 | 위치 | 역할 |
| --- | --- | --- |
| `deepmesh_demo.sh` | k8s-master `:/tmp/deepmesh_demo.sh` | **메인 시연 스크립트.** 노트북 `deepmesh_demo.ipynb` 시나리오를 그대로 옮긴 것. 공격/방어 시나리오 + 트래픽 제어 + 대시보드 초기화까지 인자 하나로 실행 |
| `cleared.sh` | k8s-master `:/tmp/cleared.sh` | **CLEARED(교차검증 통과) 판정 캡처용** 보조 스크립트 |
| `gen.sh` | 리포 `k8s/traffic-gen/configmap.yaml` (ConfigMap `traffic-gen-script`) → Pod에 `/scripts/gen.sh`로 마운트 | **상시 배경 정상 트래픽 생성기** 본체 |
| `traffic-gen` Deployment | 리포 `k8s/traffic-gen/deployment.yaml` | 위 `gen.sh`를 돌리는 Deployment (`curlimages/curl`, replica로 on/off) |

## 2. 트래픽 발생 스크립트 (배경 정상 트래픽)

- **무엇**: `traffic-gen` Deployment가 `gen.sh`를 돌려, 공개 API(`/api/**`)만 정상 사용자 모양으로 끊김 없이 호출한다. 대시보드 토폴로지의 benign(초록) 엣지가 5분 창에서 사라지지 않도록 유지하는 배경 흐름.
- **주의**: 이 Pod 자체는 사이드카 없음 + 토폴로지에서 제외(`deepmesh.topology.exclude`). 탐지 대상은 이 요청을 받은 서비스가 내보내는 east-west egress다.

실행/중지 (둘 중 편한 쪽):

```bash
# deepmesh_demo.sh 래퍼
bash /tmp/deepmesh_demo.sh live     # 배경 트래픽 시작 (replicas=1)
bash /tmp/deepmesh_demo.sh quiet    # 배경 트래픽 중지 (replicas=0)

# 또는 kubectl 직접
kubectl -n deepmesh scale deploy/traffic-gen --replicas=1   # 시작
kubectl -n deepmesh scale deploy/traffic-gen --replicas=0   # 중지
```

> 스크립트(`gen.sh`)를 고쳤을 때는 ConfigMap 갱신 후 `k8s/traffic-gen/deployment.yaml`의 `deepmesh.io/script-revision` 값을 올려 Pod를 새로 띄워야 반영된다.

## 3. 방어 시연 — 시나리오별 실행 명령

보고서 7장(그림 36–40)의 방어 시연에 대응. 사이드카가 붙은 정상 배포 상태에서 실행하면 각 판정이 나온다.

| 판정 | 시나리오 | 대상 서비스 | 실행 명령 | 보고서 |
| --- | --- | --- | --- | --- |
| **DROP** (차단) | l3 — 내부 DELETE 스윕 (T1087/T1485) | post / comment | `bash /tmp/deepmesh_demo.sh post_l3` | 그림 37 |
| **RELAY** (응답 대체) | r1 — 응답 위조 XSS (T1565) | frontend | `bash /tmp/deepmesh_demo.sh fe_r1` | 그림 38 |
| **CLEARED** (교차검증 통과) | 형제 관측 후 동일 요청 | comment | `bash /tmp/cleared.sh` | 그림 39 |
| **탐지 제한** (실패 사례) | l2 — 위조 토큰 validate (T1550/T1078) | post / comment | `bash /tmp/deepmesh_demo.sh post_l2` | 그림 40 |
- DROP/RELAY/탐지제한은 `post_*` 대신 `comment_l3` / `comment_l2` 로 comment 서비스에서도 동일하게 실행 가능.
- **단계별 로그(그림 36)**: 사이드카가 ①트래픽 감지 ~ ⑦집행까지 단계 로그를 찍는 것은 `DEMO_NARRATE` 기능(사이드카 이미지 `reverse-proxy:v5`, 이미 배포됨). 각 시나리오 실행 시 자동 출력된다.

### CLEARED가 별도 스크립트인 이유

`cleared.sh`는 CLEARED를 만들려고 순서를 강제한다: ① **형제 replica**가 먼저 같은 스캔 요청을 보내 Request Verifier에 시그니처를 심고(이때는 drop) → ② 대시보드 truncate → ③ **primary** replica가 동일 요청 → 형제가 이미 관측된 시그니처라 **CLEARED** 판정. (deepmesh_[demo.sh](http://demo.sh)의 `comment_benign`/`post_benign`은 유효 토큰 validate로 CLEARED가 나오는 다른 경로다.)

## 6. (참고) 공격 시연 — 무방어 baseline

보고서 공격 시연(사이드카 없는 상태에서 공격 성공)은 별도 매니페스트로 대상 서비스의 사이드카를 뺀 뒤 같은 공격을 실행한다.

- 무사이드카 매니페스트: 리포 `k8s/no-sidecar/{auth-service,frontend,post-service,comment-service}-deployment.yaml`
- 적용: `kubectl apply -f k8s/no-sidecar/<svc>-deployment.yaml`  → 공격 실행(예: `k1`, `fe_r1`) → 로그 캡처
- 원복: 사이드카 판(`k8s/<svc>/deployment-with-sidecar.yaml`, 단 라이브는 `reverse-proxy:v5`) 재적용
- k1 = auth Pod에서 kube-apiserver(:443) 정찰, r1 = frontend 응답에 XSS 삽입 → 클라이언트 도달

## 7. 스크립트 코드 발췌

### 7-1. `deepmesh_demo.sh` — 공격 실행부 + 사이드카 로그 캡처

```bash
# east-west: pod 안에서 실행 (노트북 run_scn, PROBE off 와 동일).
run_scn() {  # $1 title $2 pod $3 ctr $4 target $5 body $6 watch(기본 pod)
  local title=$1 pod=$2 ctr=$3 target=$4 body=$5 watch=${6:-$2}
  echo "$BAR"; echo " $title"; echo "$BAR"
  local lport=$((15000 + RANDOM % 4000))
  local script b64
  script=$(printf '%s\nexport LPORT=%s TARGET=%s WIN=%s NS=%s TOK=%s\n%s\n' \
           "$PRELUDE" "$lport" "$target" "$WIN" "$NS" "${TOK:-}" "$body")
  b64=$(printf '%s' "$script" | base64 | tr -d '\n')
  kubectl -n $NS exec "$pod" -c "$ctr" -- sh -c "echo $b64 | base64 -d | sh" 2>&1 | sed 's/^/   /'
  narr "$watch"
}

# 사이드카 최근 판정 블록(마지막 시연 [ ] 블록)만 뽑아 출력. DEMO_NARRATE 로그를 읽는다.
narr() {
  sleep 2
  echo "  사이드카 판정 로그 ($1)"
  kubectl logs -n $NS "$1" -c reverse-proxy --since=25s 2>/dev/null \
    | awk '/시연 \[/{cap=1;buf=$0;next} cap{buf=buf ORS $0; if(index($0,"집행 소요")){last=buf;cap=0}} END{if(last!="")print last}'
}
```

### 7-2. `deepmesh_demo.sh` — 방어 시연 시나리오 본문(공격 payload)

```bash
# l3 — 내부 DELETE 스윕 (DROP 대상)
B_l3=$(cat <<'BODY'
set -- --local-port "$LPORT" -X DELETE -A "$EW_UA" -H "Accept: $EW_AC"
i=1; while [ $i -le "$WIN" ]; do set -- "$@" "$TARGET/internal/posts/$i/comments"; i=$((i+1)); done
curl -s "$@" >/dev/null 2>&1
echo "[l3] DELETE /internal/posts/1..$WIN/comments (one conn)"
BODY
)

# r1 — 응답 위조 XSS (RELAY 대상). GET / 반복으로 '변조된' index.html 응답을 받는다
B_fe_r1=$(cat <<'BODY'
set -- --local-port "$LPORT" -A "$BR_UA" -H "Accept: text/html" -H "Origin: $ORG"
k=0; while [ $k -lt "$WIN" ]; do set -- "$@" "$TARGET/"; k=$((k+1)); done
curl -s "$@" >/dev/null 2>&1
echo "[r1] GET / xWIN -> frontend 가 '변조된' index.html 응답"
BODY
)

# l2 — 위조 토큰 validate (탐지 제한/실패 사례). 3종 위조 토큰을 무작위로 섞어 보낸다
B_l2=$(cat <<'BODY'
forged(){ case "$(( $(od -An -N1 -tu1 /dev/urandom) % 3 ))" in
  0) echo "Bearer eyJ...none.<rand>.";;
  1) echo "Bearer eyJ...HS256.<rand>.X";;
  *) echo "Bearer replayed_<rand>";; esac; }
set --
k=0; while [ $k -lt "$WIN" ]; do set -- "$@" --next -H "Authorization: $(forged)" "$TARGET/internal/auth/validate"; k=$((k+1)); done
shift
curl -s --local-port "$LPORT" "$@" >/dev/null 2>&1
echo "[l2] forged validate xWIN (one conn) -> auth"
BODY
)
```

### 7-3. `deepmesh_demo.sh` — 시나리오 디스패치(방어 시연 관련)

```bash
case "${1:-}" in
  post_l3)  pin; run_scn "post l3 — 내부 DELETE 스윕 (T1087/T1485)" \
              $POST_POD post-service "http://$COMMENT_IP:8080" "$B_l3";;
  post_l2)  pin; run_scn "post l2 — 위조 토큰 validate (T1550/T1078)" \
              $POST_POD post-service "http://$AUTH_IP:8080" "$B_l2";;
  fe_r1)
    pin
    W=/usr/share/nginx/html
    # (1) frontend index.html 맨 앞에 XSS 스크립트 주입 — 원본은 index.html.orig 로 백업
    #     실제 페이로드(쿠키 유출 비콘)는 6절/공격 시연 캡처 참조
    kubectl -n $NS exec $FE_POD -c frontend -- sh -c \
      "test -f $W/index.html.orig || cp $W/index.html $W/index.html.orig; \
       cat /tmp/xss_payload $W/index.html.orig > $W/index.html"
    # (2) post pod 에서 frontend 로 GET / 반복 → 위조 응답 수신
    run_scn "frontend r1 — 응답 위조 XSS (T1565)" \
      $POST_POD post-service "http://$FE_IP:80" "$B_fe_r1" $FE_POD
    # (3) 복원 (net-zero)
    kubectl -n $NS exec $FE_POD -c frontend -- sh -c "cp $W/index.html.orig $W/index.html";;
esac
```

### 7-4. `cleared.sh` (전문)

```bash
#!/bin/bash
set -u
NS=deepmesh
CP=$(kubectl -n $NS get pods -l app=comment-service -o jsonpath='{.items[0].metadata.name}')
CIP=$(kubectl -n $NS get pods -l app=comment-service -o jsonpath='{.items[1].metadata.name}')
POST=$(kubectl -n $NS get pods -l app=post-service -o jsonpath='{.items[0].status.podIP}')
scan(){ kubectl -n $NS exec "$1" -c comment-service -- sh -c "U=http://$POST:8080/actuator/env; set -- -s -o /dev/null \$U; k=1; while [ \$k -lt 10 ]; do set -- \"\$@\" \$U; k=\$((k+1)); done; curl \"\$@\""; }
scan "$CIP"    # 형제가 먼저 보냄 -> Verifier 시그니처 기록(drop 발생)
sleep 2
kubectl -n $NS exec mysql-0 -c mysql -- mysql -uroot -p<pw> -e "truncate dashboard_db.detection_event; truncate dashboard_db.stats_bucket; truncate dashboard_db.peer_benign_bucket;"
scan "$CP"     # primary -> 형제 관측됨 -> CLEARED
echo cleared_done
```

### 7-5. `gen.sh` (traffic-gen) — 배경 정상 흐름 발췌

```bash
# 정상 사용자 모양의 헬퍼
hit()  { curl -s -o /dev/null -m 10 -A "$UA" -H 'Accept: application/json' "$@"; }
get()  { curl -s -m 10 -A "$UA" -H 'Accept: application/json' "$@"; }
auth_header() { echo "Authorization: Bearer $(cat $TOKEN 2>/dev/null)"; }

flow_post_auth() {        # post->auth : 글 수정이 auth validate를 부른다
  while :; do
    T=$(cat $ANCHOR 2>/dev/null)
    [ -n "$T" ] && hit -X PUT $P/api/posts/$T -H "$(auth_header)" -H "$JSON" \
      -d "{\"title\":\"살아있는 글\",\"content\":\"$(date +%H:%M:%S)\"}"
    maybe 40 && hit $P/api/posts -H "$(auth_header)"          # 목록도 섞는다
    nap 2 7
  done
}

flow_comment_auth() {     # comment->auth : 댓글 쓰기·지우기를 쌍으로 → DB 순증 없음
  while :; do
    T=$(cat $ANCHOR 2>/dev/null)
    if [ -n "$T" ]; then
      CID=$(get -X POST $C/api/comments/$T/comments -H "$(auth_header)" -H "$JSON" \
        -d "{\"content\":\"댓글\"}" | jnum commentId)
      nap 5 9
      [ -n "$CID" ] && hit -X DELETE $C/api/comments/$CID -H "$(auth_header)"
    fi
    sleep $(between 1 3)
  done
}
```

> 위는 발췌다. 전문은 각 파일 참조 — `deepmesh_demo.sh`(약 16KB, 전체 시나리오), `k8s/traffic-gen/configmap.yaml`([gen.sh](http://gen.sh) 전문). r1 XSS 실제 페이로드는 6절(공격 시연) 및 시연 캡처 이미지에 있음.
