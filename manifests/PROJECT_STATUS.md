## 대시보드가 실제로 보여주는 것 (화면 구성 시 전제)

`Deepmesh Monitoring System` 개요 탭 기준. **공격이 번져 나가는 연출은 없다.** 있는 요소만 쓴다.

| 영역 | 내용 |
|---|---|
| 상단 카드·간선 범례 | **forward(초록) / drop(빨강) / relay(주황)** — 2026-09-19 대시보드 개편 후 표기. 이전의 benign·cleared 구분은 없어짐 |
| 서비스 토폴로지 | frontend, post, comment, auth, mysql, External 노드 + **Master Node 박스(Kubernetes API Server · Request Verifier · Pod Info Provider)**. 평소 트래픽은 초록 점선 forward 간선. 침해된 pod 노드가 강조되고 **간선 하나가 빨강(drop) 또는 주황(relay)으로 그려짐** |
| 탐지 이벤트 | 시각 + FORWARD/DROP/RELAY 배지 + "A → B" + 한 줄 설명. **평소 트래픽의 FORWARD 행이 초당 여러 개 쌓이므로 DROP·RELAY 행이 금방 밀려 내려간다** |
| 차단율 카드 | drop ÷ 판정 건수. 평소 트래픽이 함께 돌면 0.1% 수준으로 작게 나오므로 **마무리 강조용으로 쓰지 않는다** |
| 하단 | 판정 추이, 추론 지연 그래프 |

- **사이드카 프록시가 꺼져 있으면 대시보드에는 아무것도 뜨지 않는다.** 따라서 "방어 OFF = 공격 성공" 장면은 대시보드가 아니라 **터미널과 사용자 브라우저**로 보여준다.
- k1은 토폴로지에서 `auth → Kubernetes API Server` 간선으로, r1은 `frontend → post` 간선으로 나타난다.
- 훅(①)에도 대시보드를 쓰지 않는다. ①·⑧ 화면 구성은 `script/APPROVED_NARRATION_KR.md` 참조.
