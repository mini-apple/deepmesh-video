# DeepMesh 졸업과제 설명·시연 영상 스크립트 (자동차 공장 버전)

- **총 길이:** 약 9분 (540초 목표)
- **비유:** 자동차 공장 공정 분업 — 작업자 = 메인 컨테이너, 공정 출구 검사원 = 사이드카 프록시
- **시연 시나리오:** k1(요청 공격 → Drop), r1(응답 공격 → Relay)
- **청중:** 클라우드·Pod를 모르는 일반인 (교수님 지시)
- **표기:** 해설 / 질문자 / 애덤 / 해커 / 검사원 · `[화면]` 편집 지시 · `[ ]` 확정 후 채울 빈칸

## ② 왜 필요한가 (0:21–1:08)

`[화면] 기사 헤드라인 캡처 + 출처, 숫자 카드 "80~90%"`

**해설:** 먼저, 요즘 해킹이 어떻게 달라졌는지부터 보겠습니다.

**해설:** 2025년 11월 Anthropic 보고서에 따르면, 한 해킹 공격에서 전체 과정의 80에서 90퍼센트를 AI가 스스로 해냈습니다. 침투는 물론, 안으로 들어간 뒤 옆 시스템으로 번지는 것까지요.

`[화면] 기사 캡처 C3의 "lateral movement" 형광펜 강조 → 숫자 카드 "한 달 남짓, 취약점 10,000개 이상"`

**해설:** 2026년에는 약 50개 기관이 AI로 한 달 남짓 만에 심각한 취약점을 1만 개 넘게 찾아냈습니다. 공격하는 쪽도 같은 속도로 찾을 수 있으니, 결국 언젠가는 뚫린다고 봐야 합니다.

**해설:** 게다가 뚫린 뒤 공격이 안에서 번지는 속도는, 사람이 보고 대응하기엔 너무 빠릅니다.

**해설:** 그래서 저희는 질문을 바꿨습니다. "어떻게 안 뚫리게 할까"가 아니라, **"뚫린 다음 안에서 번지는 걸 어떻게 자동으로 막을 수 있을지"**로요.

## ③ 기초 개념 (1:08–2:54)

**해설:** 그 답을 보여드리려면, 요즘 웹 서비스가 어디서 돌아가는지부터 봐야 합니다. 대부분 클라우드 위에서 돌아갑니다.

**질문자:** 근데 클라우드가 정확히 뭐예요?

**해설:** 컴퓨터를 직접 사지 않고 빌려 쓰는 겁니다. 요즘 웹 서비스는 이 빌린 컴퓨터 위에서, 프로그램 하나를 여러 조각으로 나눠서 돌립니다. 이걸 **마이크로서비스 구조, MSA**라고 합니다.

**해설:** 이렇게 나누면 바쁜 조각만 골라 늘릴 수 있고, 한 조각이 멈춰도 전체가 멈추지 않습니다. 이처럼 클라우드에 맞게 만드는 방식을 **클라우드 네이티브**라고 합니다.

`[화면] 자동차 공장 전경: 승인 사무실, 차체 공정, 도장 공정, 출고장`

**해설:** 지금부턴 자동차 공장으로 비유해보겠습니다. 자동차 만드는 과정을 공정별로 나누고, 각 공정의 작업자가 자기 일만 맡는 방식입니다.

`[화면] 각 공정 작업자 머리 위에 frontend / auth / post / comment 이름표`

**해설:** 저희도 실험할 게시판을 직접 만들어 네 조각으로 나눠봤습니다. 화면을 보여주는 **frontend**가 출고 담당, 로그인을 맡는 **auth**가 승인 담당, 게시글을 맡는 **post**가 차체 공정, 댓글을 맡는 **comment**를 도장 공정에 비유해보겠습니다.

**질문자:** 공정끼리는 어떻게 소통해요?

`[화면] 공정 사이로 작업 요청서가 오감`

**해설:** 작업 요청서를 주고받습니다. 차체 공정은 작업 전에 승인 담당에게 이 지시서가 승인된 게 맞는지 묻습니다. 이렇게 오가는 요청서와 완성 부품이 바로 **네트워크 트래픽**입니다.

`[화면] 쿠버네티스 용어 자막이 공장 위에 겹쳐짐(나레이션과 동기화): 공장 전체=클러스터 / 생산관리실=마스터 노드 / 공정 구역=Pod / 작업자=컨테이너 / 같은 구역 두 개=레플리카. 각 공정 구역이 두 개씩 보임`

**해설:** 이런 공장을 실제로 운영해 주는 도구가 **쿠버네티스**입니다. 쿠버네티스 용어로 바꾸면, 공장 전체가 **클러스터**, 어느 구역에 무엇을 배치할지 정하는 생산관리실이 **마스터 노드**, 공정 구역 하나가 **Pod**, 그 구역에서 실제로 일하는 작업자가 **컨테이너**입니다. 그리고 모든 공정은 똑같은 구역을 두 개씩 운영합니다. 한 곳이 멈춰도 생산이 이어지게요. 이걸 **레플리카**라고 합니다.

`[화면] 공정 구역 출구의 검사원과 검사 카메라. 들어오는 요청서는 그대로 통과, 나가는 부품과 요청서에만 스캔 빛`

**해설:** 마지막으로, 공정 구역마다 출구에 검사원이 한 명씩 서 있습니다. 들어오는 것은 그냥 넘기고, **구역에서 밖으로 나가는 것만 전부 검사합니다.** 이 검사원이 **사이드카 프록시**, 오늘의 주인공입니다.

`[화면] 모든 공정 구역에 검사원이 서 있고, 생산관리실과 선으로 연결되는 그물 구조. 자막 "서비스메시"`

**해설:** 이렇게 구역마다 검사원을 붙이고 생산관리실에서 한꺼번에 관리해서, **작업자는 그대로 둔 채 오가는 요청서만 통제하는** 구조를 **서비스메시**라고 합니다. 저희 과제는 이 서비스메시를 새로운 구조로 만드는 것입니다.

## ④ 문제: 측면이동 (2:54–4:04)

**질문자:** 근데 공장 정문에 경비가 있잖아요? 구역마다 검사원까지 꼭 둬야 해요?

`[화면] 숫자 카드 "44.5% 소프트웨어 취약점", "27.2% 약한 인증", "21% 설정 실수" + 출처 "Google Cloud Threat Horizons Report H1 2026 · 2025년 하반기 데이터"`

**해설:** 정문은 생각보다 쉽게 뚫립니다. 구글 클라우드 보고서에 따르면, 공격자가 처음 들어온 경로의 44.5퍼센트는 패치하지 않은 소프트웨어의 취약점, 27.2퍼센트는 약하거나 없는 인증 정보, 21퍼센트는 설정 실수였습니다. 이런 틈 하나면, 작업자 한 명이 매수되는 셈입니다.

`[화면] 작업자 목에 걸린 사원증. 자막 "작업지시서와는 다른, 생산관리 서버 접속용 사원증"`

**해설:** 쿠버네티스는 공정 구역마다 생산관리 서버에 접속할 수 있는 사원증, **서비스 계정 토큰**을 기본으로 넣어 둡니다. 이 권한이 과하면, 매수된 작업자는 생산관리 서버에 접속해 공장 정보를 캐고, 결국 공장 전체를 장악할 수 있습니다.

`[화면] 빨간색이 한 구역 → 생산관리실 → 가짜 구역 → 공장 전체로 번짐`

`[화면] 자막 "측면이동 (Lateral Movement)"`

**해설:** 이렇게 처음 들어온 한 곳을 발판 삼아, 옆에 있는 다른 시스템으로 옮겨 가며 장악 범위를 넓히는 공격을 **측면이동**, 영어로 **래터럴 무브먼트(lateral movement)**라고 합니다. 문제는 이 일이 **공장 안에서 시작된다**는 겁니다. 정문 보안은 외부인 출입만 보기 때문에, 이미 구역 안에 있는 작업자가 무엇을 내보내는지는 보지 못합니다.

## ⑤ 작동 원리 (4:04–6:01)

**해설:** 바로 이 빈틈을 구역 출구의 검사원이 지킵니다. 이 검사원에게는 크게 **세 가지 기술**이 들어갑니다.

`[화면] 출구 카메라가 나가는 것 5개를 한 줄씩 스캔해 흑백 이미지 한 장을 만듦. 받는 곳 표시는 가려짐`

**해설:** 첫 번째로, **나가는 트래픽만 스캔합니다.** 구역이 내보낸 것 다섯 개를 한 줄씩 쌓아 흑백 이미지 한 장으로 만듭니다. 이때 한 줄에는 요청 종류, 경로, 크기, 시간 간격 같은 스무 가지 특징이 담깁니다.

**질문자:** 그 이미지만 보고 이상한지 어떻게 알아요?

`[화면] 정상품 이미지들이 울타리 안에 모이고, 벗어난 하나가 빨갛게 표시됨. 자막 "사람 눈엔 거의 똑같음"`

**해설:** 정상품의 모습만 외워 두면 됩니다. 여기에 쓰는 두 번째 기술이 **딥러닝 이상탐지 모델**입니다. 외워 둔 정상과 다르게 생긴 것이 나오면 이상으로 판단합니다. 공격은 불량품처럼 드물기 때문에, 공격 데이터 없이 평소 나가던 정상 이미지만으로 학습시킵니다. 이렇게 학습한 검사원은 사람 눈에 거의 똑같아 보이는 것도 미세한 차이를 잡아냅니다.

`[화면] 자막 "공정(서비스)마다 따로 학습"을 짧게 표시 → 큰 선생님 검사기에서 작은 학생 검사기로 판단이 옮겨 가는 도식(포스터의 Teacher → Student 도식 재사용)`

**해설:** 마지막으로, **검사기를 가볍게 만듭니다.** 구역마다 검사원이 있으니, 검사가 느리면 공장 전체가 느려집니다. 그래서 크고 세밀한 선생님 검사기를 먼저 학습시킨 뒤, 작은 학생 검사기가 그 판단을 보고 따라 배우게 합니다. 이 방식을 **지식증류**라고 합니다.

`[화면] 신호등: 초록 통과 / 빨강 반려 / 주황 교체`

**해설:** 그런데 의심만으로 막으면 정상 생산까지 멈출 수 있습니다. 그래서 **한 번 더 확인합니다.**

`[화면] 검사원이 생산관리실 확인 담당에게 전화`

**해설:** 나가는 요청서가 의심스러우면, 검사원이 생산관리실에 묻습니다. "옆 구역에서도 이런 요청서를 보낸 적 있나요?" 없다면 반려합니다. **차단, Drop**입니다.

`[화면] 검사원이 옆 구역에 같은 작업 요청 → 두 부품을 나란히 비교 → 옆 구역 부품이 출고됨`

**해설:** 나가는 부품이 의심스러우면, 옆 구역에 똑같은 작업을 요청해 받은 부품과 비교합니다. 둘이 다르면 의심받은 쪽 대신 **옆 구역 부품을** 내보냅니다. **교체, Relay**입니다. 괜히 의심했더라도 고객은 정상 부품을 받으니 생산은 멈추지 않습니다.

**해설:** 문제가 없으면 그대로 **통과, Forward**입니다.

`[화면] 도장 작업자 → 도장 출구 검사원 → 차체 구역. "도장이 보낸 요청서 = 차체가 받는 요청서" 강조`

**질문자:** 근데 왜 들어오는 요청서는 검사 안 해요?

**해설:** 모든 구역 출구에 검사원이 있기 때문입니다. 들어오는 요청서는 **보낸 구역의 출구에서 이미 검사를 거쳤습니다.** 그리고 매수된 작업자가 옆으로 번지려면 결국 뭔가를 밖으로 내보내야 합니다. 그래서 나가는 것만 잘 지키면 됩니다.

## ⑥ 시연 (6:01–8:03)

> 녹화 전 조건: k1·r1 모두 사전검증(대시보드에 단일 세션 1개 + 이상 판정 1회 확인). 실제 동작 범위만 녹화.
> 구성: 시나리오마다 **(1) 사이드카 프록시 없을 때 공격 성공 → (2) 사이드카 프록시 있을 때 대시보드 Drop/Relay로 공격 실패** 순서.
> **DeepMesh는 팀 이름이므로 시스템을 가리키는 데 쓰지 않는다.** 개별 구성요소는 '사이드카 프록시', 구조 전체는 '서비스메시'.
> 나레이션은 비유 없이 실제 용어(pod, 사이드카 프록시, API 서버, 대시보드)로만 말한다.
> **화면 소스가 섞인다.** 시나리오 설명 컷(k1 설명, r1 설명)만 AI 생성 영상이고, 나머지는 전부 실제 녹화다.
> - AI 컷: 화면 구석에 "연출 이미지" 상시 표기. 공장 비유 장면 위에 실제 용어 라벨을 붙여 ③④에서 배운 대응을 다시 짚는다.
> - 실제 녹화 컷: 화면 구석에 "실제 시스템 화면" 상시 표기.
> - 두 소스가 바뀌는 지점마다 짧은 전환(0.3초 화이트 플래시 등)으로 경계를 분명히 한다.

### 정상 상태 (6:01–6:20)
`[화면] 좌: 게시판 화면 / 우: 대시보드 '개요' 탭. 상단 카드(forward·drop·relay)와 서비스 토폴로지가 전부 초록 forward 간선, 탐지 이벤트 목록은 비어 있음`

**해설:** 그럼 이제 이상 트래픽이 정말 막히는지 실제 시스템에서 확인해보겠습니다. 버추얼머신 네 대로 쿠버네티스 클러스터를 세우고 저희 게시판을 올렸습니다. 네 개의 서비스가 각각 pod로 돌아가고, 모든 pod에는 사이드카 프록시가 붙어 있습니다. 이 화면은 관리자가 전체 클러스터 현황을 볼 수 있는 대시보드입니다. 지금은 정상적인 트래픽 부하를 주고 있고, 트래픽이 모두 초록색 포워드 간선으로 보이는 것을 확인할 수 있습니다.

### 시나리오 1 — k1: 정찰 차단, Drop (6:20–7:12)
`[화면] AI 생성 영상 · "연출 이미지". ④에서 만든 장면을 재사용한다: 매수된 승인 담당 작업자가 목에 건 사원증을 들고 생산관리실 문으로 향함 → 생산관리실 대형 모니터를 들여다봄. 장면 위 라벨 "auth pod = 승인 담당" · "서비스 계정 토큰 = 사원증" · "API 서버 = 생산관리 서버". 하단 자막 "시나리오 1 · k1 · MITRE T1613"`

**해설:** 그럼 첫 번째 공격을 진행해보겠습니다. auth pod 하나가 이미 탈취됐다고 가정합니다. 공격자는 pod에 기본으로 들어 있는 **서비스 계정 토큰**으로 쿠버네티스 API 서버에 접속해, 클러스터 정보를 캐려 합니다.

`[화면] ── 여기서부터 실제 녹화 ── 탐지 OFF. 터미널만 보여준다(대시보드는 사이드카 프록시가 꺼져 있어 이벤트가 없다). auth pod에서 API 서버로 보낸 요청이 연결에 성공하는 출력. 토큰 문자열·내부 IP 모자이크`

**해설:** 먼저 사이드카 프록시를 끈 상태입니다. auth는 평소 API 서버를 호출할 일이 없지만, 감시하는 장치가 없으면 이 요청은 그대로 API 서버까지 도달합니다.

`[화면] 방어 ON. 대시보드: drop 카드가 0→1로 오르고, 토폴로지에서 auth 노드에서 Master Node 박스 안의 Kubernetes API Server로 빨간 간선이 그려진다. 탐지 이벤트에 DROP 행 추가. 좌측 터미널은 연결 실패`

**해설:** 이제 사이드카 프록시를 켭니다. auth pod가 한 번도 보낸 적 없는 방향, 즉 API 서버로 나가는 요청을 곧바로 이상 트래픽으로 잡아냅니다. 대시보드에 빨간 **drop**이 뜨고, 요청은 API 서버에 닿지 못합니다. `[실제 터미널 결과로 확정: 연결 끊김 / 응답 코드]`

### 시나리오 2 — r1: 응답 교체, Relay (7:12–8:03)
`[화면] AI 생성 영상 · "연출 이미지". 출고장에서 고객에게 나갈 완성품 상자에 누군가 몰래 작은 이물질을 끼워 넣음 → 그 상자가 그대로 고객 손에 전달되고, 고객이 상자를 여는 순간 이물질이 작동. 장면 위 라벨 "frontend = 출고 담당" · "악성 스크립트 = 몰래 넣은 이물질" · "사용자 브라우저 = 고객". 하단 자막 "시나리오 2 · r1 · MITRE T1565"`

**해설:** 두 번째 공격은 공격자가, frontend가 사용자에게 내보내는 첫 화면에 악성 스크립트 한 줄을 몰래 끼워 넣는 **크로스 사이트 스크립트** 공격입니다. 화면을 연 사용자의 브라우저에서 실행되는 악성 스크립트입니다.

`[화면] ── 여기서부터 실제 녹화 ── 탐지 OFF. 좌: 변조된 index.html 응답 원문(주입된 script 강조) / 우: 사용자 브라우저에서 그 스크립트가 실행되는 장면. 자막 "시연용 무해한 테스트 스크립트"`

**해설:** 사이드카 프록시가 꺼져 있으면, 변조된 화면이 그대로 사용자에게 전달되고 스크립트가 사용자 브라우저에서 실행됩니다. 사용자는 아무것도 모른 채 당합니다.

`[화면] 방어 ON. 대시보드: relay 카드가 0→1로 오르고, 토폴로지에서 frontend 노드가 표시되며 frontend → post 주황 간선이 그려진다. 탐지 이벤트에 RELAY 행 추가. 우측 사용자 브라우저는 스크립트가 빠진 정상 화면`

**해설:** 사이드카 프록시를 켜면, frontend의 응답이 평소와 다르다는 걸 탐지합니다. 그리고 똑같이 떠 있는 두 번째 replica에 같은 화면을 요청해 비교하고, 변조된 쪽 대신 정상 응답을 내보냅니다. 대시보드에는 주황색 **relay**가 뜨고, 사용자에게는 스크립트가 빠진 정상 화면이 표시됩니다.

## ⑦ 결과 (8:03–8:46)

`[화면] 숫자 카드 3장: "Recall 86.7~100%" → "오탐률 1.3% 이하" → "CPU 추론 약 1ms (0.36~1.13ms)". 출처 자막 "2026 졸업과제 포스터 · 자체 실험 결과"`

**해설:** 이제 성능을 숫자로 정리해 보겠습니다. 저희는 쿠버네티스 클러스터를 직접 구성하고, 정상·공격 트래픽을 자체 게시판 환경에서 수집해 모델을 학습했습니다.

**해설:** 정상 트래픽만 학습한 이 모델은 측면이동 공격을 각각 **재현율 86.7퍼센트에서 100퍼센트**로 탐지했습니다. 정상을 공격으로 잘못 본 비율은 **1.3퍼센트 이하**였습니다.

`[화면] 파라미터 축소 도식: 314.69K → 1.2K~12.6K. 이어서 CPU 추론 지연 그래프`

**해설:** 그리고 지식증류를 이용해, 모델의 파라미터 크기를 **31만 개에서 약 천에서 만 개**의 파라미터 크기로 경량화했습니다. 덕분에 GPU 없이 CPU만으로도 **모델 판정에 약 1밀리초 안팎**이 걸렸습니다.

**해설:** 이제 처음의 그 장면으로 다시 돌아가 보겠습니다.
