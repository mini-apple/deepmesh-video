# RECORDING_GUIDE

① 훅과 ⑥ 시연 녹화 지침. **나레이션을 먼저 확정하고, 화면을 거기에 맞춰 편집한다.**

## 원칙: 오디오가 기준, 화면이 따라간다

- **음성은 늘이거나 줄일 수 없다.** 배속을 올리면 바로 어색해진다. 1.05배 정도가 한계다.
- **화면 녹화는 자유롭게 줄이고 늘릴 수 있다.** 기다리는 구간은 배속, 빈 구간은 컷, 모자라면 정지 화면이나 천천히 줌으로 채운다.
- 그래서 **녹화하면서 나레이션에 맞추려고 하면 안 된다.** 맞추는 건 편집에서 한다.

## 순서

| 순서 | 할 일 | 상태 |
|---|---|---|
| 1 | k1·r1 사전검증 — 대시보드에 DROP/RELAY가 실제로 뜨는지 확인 | **완료 (2026-09-19)** |
| 2 | ②③ 재녹음 + ④⑤⑥⑦⑧ TTS 녹음 | 진행 중 |
| 3 | 터미널 쉘 스크립트 실행 화면 확인 (글자 크기·창 배치) | 대기 |
| 4 | **시연 녹화** | 아래 컷별 목표 초를 보면서, 여유 있게 길게 녹화한다 |
| 5 | 편집 | 나레이션 위에 화면을 얹고 배속·컷으로 맞춘다 |

> 시연은 주피터 노트북이 아니라 **터미널 쉘 스크립트**로 실행한다. 녹화 전에 한 번 돌려 보고
> 폰트 크기(최소 16pt)와 창 배치(좌: 터미널 / 우: 대시보드)를 먼저 정한다.

훅 영상은 따로 찍지 않는다. 4번 녹화분(특히 방어 OFF 장면)에서 잘라 쓴다.

## ⑥ 컷별 목표 시간 (나레이션 실측 전 예측)

합계 약 112초. 실제 녹화는 **각 컷마다 목표의 2배 이상 길게** 찍어 둔다.

| 컷 | 화면 | 나레이션 | 녹화 시 유의점 |
|---|---|---|---|
| 06-1 | 게시판 + 대시보드 초록 | 28초 | 정상 상태를 30초 이상 그대로 둔다. 배속으로 줄이기 쉬움 |
| 06-2 | k1 설명 | 14초 | **녹화 안 함.** AI 생성 영상(④ 장면 재사용) |
| 06-3 | k1 방어 OFF — 터미널에서 API 서버 도달 | 10초 | 명령 입력부터 응답까지 전부 녹화 |
| 06-4 | k1 방어 ON — 대시보드 DROP | 14초 | **차단 카드 0→1, auth→Kubernetes API Server 간선, 이벤트 행이 뜨는 순간을 반드시 포함.** 뜬 뒤 10초 더 녹화 |
| 06-5 | r1 설명 | 15초 | **녹화 안 함.** AI 생성 영상(출고장 이물질 장면, 신규 생성) |
| 06-6 | r1 방어 OFF — 사용자 브라우저에서 스크립트 실행 | 11초 | 복원되기 전에 새로고침해서 잡아야 한다 |
| 06-7 | r1 방어 ON — 대시보드 RELAY + 정상 화면 | 21초 | **relay 카드 0→1, frontend→post 간선, RELAY 행이 뜨는 순간 포함.** 뜬 뒤 10초 더 |

## 녹화 규칙

- **한 컷마다 앞뒤로 3초씩 여유**를 두고 시작·종료한다. 편집에서 잘라 낼 여유분이다.
- **마우스를 천천히 움직인다.** 빠른 커서는 영상에서 읽기 어렵다.
- **탐지 이벤트 목록은 FORWARD 행이 계속 쌓여 DROP·RELAY 행이 금방 밀려난다.** 공격 직전에 평소 트래픽 생성기를 잠시 멈추거나, 이벤트 행이 뜨는 순간을 편집에서 정지 화면으로 잡는다.
- **이벤트가 뜬 뒤 최소 10초를 더 녹화한다.** 편집에서 정지 화면으로 늘려 쓸 수 있다.
- 실패해도 다시 찍으면 되니 **같은 장면을 2~3번** 찍어 둔다.
- 1920×1080, 30fps 고정. 브라우저 확대는 125~150%로 올려 글자가 읽히게 한다.
- **토큰 문자열과 내부 IP는 모자이크 대상**이므로, 녹화 시 위치를 기억해 둔다.

## 편집에서 길이 맞추는 방법

화면이 나레이션보다 **길면**: 기다리는 구간 배속(4~8배), 중간 컷 삭제.
화면이 나레이션보다 **짧으면**: 이벤트가 뜬 화면을 정지시키고 천천히 확대, 또는 해당 영역 확대 컷을 덧붙인다.
